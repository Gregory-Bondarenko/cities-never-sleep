# ADR-0001. Раскладка «аналитика → артефакты → витрина»

- Статус: Принято
- Дата: 2026-10-29

## Контекст

Продукт состоит из тяжёлой обработки растров и лёгкого сайта. Если расчёты попадут во фронтенд, результаты станут невоспроизводимыми, а сайт тяжёлым.

## Решение

Репозиторий делится на три слоя с однонаправленной связью:

1. `analytics/`: загрузка, обработка, метрики, ноутбуки.
2. `data/processed/` и `analytics/exports/`: небольшие артефакты с метаданными.
3. `web/`: только визуализация экспортов.

Фронтенд не рассчитывает метрики и тренды. Сырые и промежуточные данные в git не попадают.

## Последствия

- Любая цифра на сайте прослеживается до артефакта и кода, который его собрал.
- Нужен явный контракт артефактов (см. [architecture.md](../architecture.md)).
- Изменение схемы артефакта требует согласованного изменения витрины.
