# Архитектура

Документ описывает устройство продукта: слои, контракты данных и правила их изменения. Раздел «Текущее состояние» отражает то, что уже есть в коде; раздел «Целевое состояние» служит ориентиром и меняется только через ADR.

## Слои

```
 Источники            Аналитика (analytics/)                     Артефакты               Витрина (web/)
┌──────────────┐   ┌─────────────────────────────────────┐   ┌──────────────────┐   ┌──────────────────┐
│ Zenodo VNL   │──▶│ sources/   загрузка, манифест        │   │ data/processed/  │   │ только чтение    │
│ Wikidata     │──▶│ process/   обрезка, нормализация     │──▶│ analytics/       │──▶│ JSON / Parquet / │
│ OSM (план)   │──▶│ metrics/   зональная статистика (план)│   │   exports/       │   │ PMTiles          │
│ Black Marble │──▶│ notebooks/ разведочный анализ        │   │ + *.meta.json    │   │                  │
└──────────────┘   └─────────────────────────────────────┘   └──────────────────┘   └──────────────────┘
       raw                     interim                           processed / exports
  (не в git)               (не в git)                           (в git, небольшие)
```

Связи между слоями однонаправленные. Витрина не знает об устройстве аналитики и опирается только на контракты артефактов.

## Хранение данных

| Каталог | Содержимое | В git | Кто пишет |
|---|---|---|---|
| `data/raw/<источник>/` | исходные файлы и `manifest.json` с контрольными суммами | нет | `cns fetch-*` |
| `data/interim/<источник>/` | обрезанные и нормализованные растры | нет | `cns process-*` |
| `data/manual/` | ручные выгрузки (Росстат XLSX) | нет | человек |
| `data/processed/<набор>/` | агрегаты для анализа (Parquet + CSV) | да | `cns` |
| `analytics/exports/` | облегчённые выгрузки для витрины | да | `cns export-*` (план) |

Ограничение на размер артефакта в git: до 10 МБ на файл. Всё, что больше, собирается локально или публикуется отдельным релизным вложением.

## Контракт артефакта

Каждый набор в `data/processed/` и `analytics/exports/` состоит из файла данных и файла `<имя>.meta.json`. Обязательные поля метаданных:

| Поле | Значение |
|---|---|
| `schema_version` | версия схемы набора по SemVer, независимая от версии пакета |
| `source` | источник или список источников |
| `built_at` | дата и время сборки в UTC (ISO 8601) |
| `package_version` | версия пакета `cities-never-sleep`, собравшего набор |
| `n_rows` | число строк |
| `license_note` | лицензия исходных данных |

Правила версии схемы: переименование или удаление столбца повышает MAJOR, новый столбец повышает MINOR, исправление значений без смены структуры повышает PATCH. Витрина проверяет MAJOR при загрузке.

Запись метаданных выполняется функциями `build_meta` и `write_meta` из `citiesneversleep/meta.py`; `write_meta` отклоняет набор без обязательных полей.

### Набор `population/ru_cities_population`, схема 1.1.0

| Столбец | Тип | Описание |
|---|---|---|
| `city_id` | строка | идентификатор Wikidata (`Q…`), ключ города |
| `name` | строка | название на русском языке |
| `oktmo` | строка | нормализованный код ОКТМО или исходное значение, если код некорректен |
| `oktmo_status` | строка | `ok` (11 цифр), `short` (8 цифр, Москва и Санкт-Петербург), `invalid`, `missing` |
| `population` | целое | численность населения |
| `date` | дата UTC | дата значения (свойство P585), может отсутствовать |
| `year` | целое | год из `date` |
| `rank` | строка | ранг утверждения в Wikidata: `preferred`, `normal`, `deprecated` |
| `method` | строка | способ определения (P459), например `Q39825` для переписи; может отсутствовать |
| `is_primary` | логический | основное значение для пары «город × год» |
| `n_values` | целое | число различных значений года среди неустаревших утверждений |
| `is_conflict` | логический | значения года расходятся |

Правило выбора основного значения: ранг `preferred` раньше `normal`, перепись раньше оценки, более поздняя дата внутри года, затем большее значение. Устаревшие утверждения и строки без даты основными не бывают. Для анализа используются только строки с `is_primary = true`.

Дополнительные поля метаданных: `fetched_at` (дата выгрузки из Wikidata), `n_cities`, `year_min`, `year_max`, `n_years`, `n_primary`, `n_conflict_city_years`, `selection_rule`, `oktmo_status_by_city`, `query`.

### Набор `cities/ru_cities`, схема 1.1.0

Справочник городов, одна строка на `city_id`.

| Столбец | Тип | Описание |
|---|---|---|
| `city_id` | строка | идентификатор Wikidata |
| `name` | строка | название на русском языке |
| `oktmo`, `oktmo_status` | строка | как в наборе населения; при нескольких кодах предпочитается корректный |
| `coverage` | строка | ветвь отбора по ADR-0006: `p17_russia` или `oktmo_only` |
| `lat`, `lon` | число | координаты (P625), WGS 84 |
| `population_latest` | целое | последнее основное значение населения |
| `population_latest_year` | целое | год этого значения |

### Набор `lights/city_lights`, схема 1.0.0

Город × год, контур по ADR-0005.

| Столбец | Описание |
|---|---|
| `city_id`, `year` | ключ |
| `radius_km` | радиус круга r |
| `sol` | Σ min(L, 3 276,7)·A внутри r: L в нВт/см²/ср, A площадь пикселя в км² (ADR-0007) |
| `sol_unclipped` | то же без общего порога |
| `sol_r05`, `sol_r2` | то же для 0,5·r и 2·r, для оценки чувствительности к радиусу |
| `lit_area_km2` | площадь пикселей с L > 0 внутри r |
| `mean_radiance`, `max_radiance` | средняя (с весом площади) и максимальная яркость внутри r |
| `n_pixels`, `share_nan` | число пикселей в круге и доля пропусков |
| `n_near_cap`, `flag_near_cap` | пиксели выше 90% предела хранения int16 (с учётом деления на 10 до 2021 года) |
| `flag_nan` | доля пропусков больше 10% |

### Набор `trends/city_trends`, схема 1.2.0

Один город на строку: координаты и население из справочника; `lights_rel_pct_per_year`, `lights_rel_p_value`, `brightness_decile`; `lights_class` (относительно индекса своей децили яркости, ADR-0008); `lights_nat_pct_per_year` и `lights_class_national` (относительно национального индекса, ADR-0007); `lights_raw_pct_per_year`; `lights_rel_pct_per_year_pre2022` и `lights_class_pre2022` (только 2012–2021); `lights_rel_pct_per_year_r2` (круг 2·r); `population_pct_per_year`, `population_p_value`, `population_class`; `quadrant`; флаги `any_flag_nan`, `any_flag_near_cap`, `flag_point_source` (максимальная яркость пикселя за последние 3 года более чем в 10 раз выше, чем за первые 3). Порог стабильности 1% в год, уровень значимости 0,05, минимум 8 лет для яркости и 5 лет для населения.

### Выгрузка `analytics/exports/cities.json`, схема 1.1.0

Единственный источник данных витрины. Поля верхнего уровня: `years`, `national_index`, `cities`. Для города: `id`, `name`, `lat`, `lon`, `population`, `coverage`, `decile`, `lights_class`, `lights_pct`, `lights_class_national`, `population_class`, `population_pct`, `flags` (`point_source`, `near_cap`, `nan`) и `series` с рядами `lights_rel` (к индексу децили, среднее города = 1), `sol` и `population` по годам, `yoy` с логарифмом изменения суммы излучения для пар лет из `story.jump_pairs`. Блок `story.jump` хранит медианное изменение и долю растущих городов для каждой пары: витрина показывает эти числа, а не считает их. Собирается командой `cns export-web`.

### Прочие выгрузки для витрины

| Файл | Содержимое | Как собирается |
|---|---|---|
| `lightmap_<год>.png` | ночной снимок, максимум по блокам 10×10, логарифмическая шкала | `cns export-lightmap --year` на раннере (`data-refresh`, источник `lightmap`) |
| `coastline.json` | береговые линии суши Natural Earth 1:50m в рамке России, без политических границ | `node scripts/coastline.mjs` |

Радиус кругового контура вычисляется из `population_latest` функцией `process/boundaries.radius_km` (ADR-0005) и в справочнике не хранится.

## Целевое состояние (v1.0.0)

### Ключ города

Единый идентификатор города `city_id` равен идентификатору Wikidata (`Q…`). ОКТМО хранится как атрибут и проходит нормализацию: 11 знаков, только цифры; для городов федерального значения допускается 8 знаков. Выбор `city_id` вместо ОКТМО обоснован тем, что ОКТМО в Wikidata заполнен не у всех городов и встречаются ошибочные значения.

### Наборы данных

| Набор | Зерно | Ключ | Основные поля |
|---|---|---|---|
| `cities` | город | `city_id` | `name`, `oktmo`, `region`, `lat`, `lon`, `geometry_source` |
| `city_population` | город × год | `city_id`, `year` | `population`, `source`, `is_census` |
| `city_lights` | город × год | `city_id`, `year` | `sol` (сумма излучения), `lit_area_km2`, `mean_radiance`, `n_valid_months`, `flags` |
| `city_trends` | город | `city_id` | наклон тренда, значимость, класс динамики, сравнение с населением |

Состав полей уточняется в вехах v0.2.0–v0.4.0, финальная схема фиксируется в ADR.

### Конвейер

```
fetch-*  →  process-*  →  build-marts  →  export-web
 raw         interim       processed        exports
```

Каждая стадия запускается отдельно и идемпотентна. Полный прогон описывается в `Makefile`; при росте числа стадий допускается переход на DuckDB с dbt, решение оформляется отдельным ADR.

## Качество

- `ruff` и `pytest` на каждый PR, без обращений к сети.
- Отдельный workflow `network` проверяет доступность Zenodo и Wikidata по расписанию и вручную; в обязательные проверки PR он не входит.
- Проверки данных (уникальность ключей, формат ОКТМО, диапазоны значений) выполняются функциями в `analytics/citiesneversleep/validate/` и покрываются тестами на синтетических данных.
